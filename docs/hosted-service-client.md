# The OpenProse service from the CLI

`prose cli` reaches the OpenProse hosted service for pricing, hosted runs, run records, saved programs, published results, jobs, the wallet and organizations. These commands are service operations. They do not select a model harness or run anything locally. `prose <FILE>` with the default `openprose` harness still reports `HOSTED_UNAVAILABLE`; use `prose cli run submit` to run hosted.

```sh
prose cli service triage --json
prose cli service status --json
prose cli run quote --json
prose --output jsonl cli run submit hello.prose.md --input topic=otters --model model-luna --yes
prose --output jsonl cli run watch <RUN_ID> --after 12
prose cli run show <RUN_ID> --json
prose cli run download <RUN_ID> --output-dir ./out
prose cli wallet balance --json
prose cli service capabilities --json
prose cli service operations --json
prose cli service guide
```

Start with `cli service capabilities`: one page (or, with `--json`, one JSON line) with the grammar, every environment variable the CLI reads, the exit code of every error code (`exitCodes`: `{exit, retryable, meaning}`, so a script can `case $?` and then read `problem.code`), and every command with runnable examples. `cli service operations` prints a summary table of every command (operation, effect, whether it needs `--yes`, usage); with `--json` it prints the machine-readable manifest as the envelope's `result`: every command (as its argv, `["cli", "run", "submit"]`) with its options, service interaction id, confirmation rule, result schema, exit codes and examples. `--output jsonl` prints one record line per command, and `| head` is safe in every mode. `--help` of a service command or group in a JSON mode (`prose --output json cli run --help`) prints the envelope whose result is `{help, operations}`. Every command also has `--help`, including `cli auth`, `cli org list` and `cli package`. Each topic has an Examples section taken from the manifest (a group shows one example per command), and each verb's help ends with its exit codes. When an option has a default, even one the service applies (`cli wallet usage` covers the last 30 days; `run submit --model` uses the service's default model), the help states it. For example, `run submit` and `run watch` exit 21 when they stop following a run that continues; resume with `details.resumeArgv` and never submit again. `cli auth login --help` explains the device flow, which needs a person; without one, set `OPENPROSE_API_KEY` instead.

To learn where a session stands, run `prose cli service triage --json` first. One call reports whether the service is reachable, whether the key works (and which variable to set when it does not), the balance (prices only), the default organization, the five newest runs, the jobs, and `nextCommands`, a list of follow-up argvs. Each section carries its own `problem`, so a failing read does not hide the rest, and the command exits 0 whenever it produces the report. See [discovery](service/discovery.md#cli-service-triage).

For the workflow rather than the facts, read `prose cli service guide`: which key a command uses, `--yes` and `--preview`, what each exit means and how to resume after exit 21, paging, how to get a run's answer, and recipes for submit-and-wait, publishing a result and creating a webhook job. Its text is [`cli/shared/service/guide.v1.md`](../cli/shared/service/guide.v1.md), printed byte for byte by both builds; `--json` returns its sections as `{"sections":[{"id","title","body"}]}` in the usual envelope. Every `prose cli ...` command in it is checked against the manifest.

## Confirmation

Commands never prompt. A command that spends money, publishes, deletes or cannot be reversed requires `--yes`. Without it, the command exits 2 with `CONFIRMATION_REQUIRED`, says in `details.reason` what `--yes` would do (the manifest's `confirmReason`, also on the `--yes` line of the command's help: rotating a webhook secret invalidates the old one now, detaching a contract stops that program, unpublishing removes the public page), and prints the exact planned request. The plan's `summary` shows the non-secret body fields (`model`, `programRef`, `inputKeys`, `amount_cents`, `slug` and similar; never secrets, program text or input values); human output prints it as `Summary:` (cents also in dollars). For `run submit`, `program draft` and a paid `job create`, the plan also includes the server's hold quote, a flat hold independent of program and model (`run quote` says the same; the price is known only after the run settles). `--preview` prints the plan for any mutation and sends nothing. Before any confirmation, `run submit` and `program draft` check `--model` against `cli model list` (an unknown name lists the three nearest and `details.suggestedArgv` retries with the nearest), `org create` checks the slug rule, and `job create|update|configure` check the spec against the closed per-type schema published as the operation's `spec` in `cli service operations --json`, reporting every problem at once in `details.violations`. A webhook job with no `program_ref` starts no runs: its plan is effect `write` with no hold.

## Runs

`run submit` always starts a live session. It records the session in a private journal (`$XDG_STATE_HOME/openprose/cli/production/runs/`, mode 0600, never the key) before contacting the service. `run watch`, `run input` and `run cancel` use that journal (or `--session UUID`) to follow, steer or cancel a live run. Without either they read the run record: `watch` reports an ended run, `cancel` reports it as `already_ended` (exit 0), and `input` refuses it with a non-retryable `SERVICE_WRITE_CONFLICT`. A run still live elsewhere exits 2 naming the machine that submitted it.

Ctrl-C, a lost stream, or reaching the `--wait` deadline, detaches from the run without cancelling it; the error carries the run id and `details.resumeArgv`, the exact `run watch` arguments. Never resume by submitting again: that starts a second paid run. Only `run cancel --yes` cancels. A cancelled run may keep its wallet hold reserved for up to 15 minutes, so the CLI reports `reserved` next to `available` balance.

If a submission cannot be confirmed after a dropped connection, the CLI exits `RUN_SUBMISSION_AMBIGUOUS` instead of submitting again. Check `prose cli run list` (the error names the exact command).

`run show` prints the manifest (status, files, price) and never the final response text. Read outputs with `run show <RUN_ID> --file outputs/result.json` or `run download`. `run watch <RUN_ID> --after 0` replays the stream, and its terminal event carries the response. `cli result` is different: it reads results that an owner published from a public program (`OWNER/SLUG`), not run records.

A bare `SLUG` in `program show` and `run submit --from` names one of your own programs. The CLI reads its owner from the program's revisions, so you never need to know your handle.

## Output and errors

JSON results follow `service-operation.schema.json`; JSONL streams follow `service-event.schema.json` and end with exactly one terminal line. In `--output jsonl`, list commands print one `service-record.schema.json` line per item and end with one `service-page.schema.json` line carrying `count`, `nextBefore` and the rest of the result in `meta`. Every epoch-millisecond time `X` also appears as `X_iso` (RFC 3339 UTC). Human output shows money in dollars, prints `No <things>.` for an empty list, and ends with copyable `Next:` commands (and a full `Next page:` command). Every JSON line is canonical: compact, object keys sorted at every depth, one line per document. Both builds of `prose` print the same bytes, so you can hash or diff output. A paged result carries `nextBefore`; the envelope names no service environment. Output shows prices only. Signed file URLs are never printed. Share links and webhook secrets appear only in the result of the command that creates them.

| Exit | Meaning |
| --- | --- |
| 0 | Success |
| 2 | Invalid invocation, or `CONFIRMATION_REQUIRED` |
| 10 | Authentication, balance, capability not available for the account, not found, conflict or unavailable service |
| 21 | Detached: watch deadline reached, interrupt, or stream lost (the run continues; resume with `details.resumeArgv`) |
| 22 | Hosted run failed, or the submission is ambiguous |
| 24 | Cancelled (`HOSTED_RUN_CANCELLED`: the run was cancelled on the service) |

Service commands always start with `cli`. `prose run submit hello.prose`, `prose job list`, `prose wallet balance`, `prose login` and `prose models` exit 2. The Action and `details.suggestedArgv` give the exact `prose cli ...` command, with your global options kept. Nothing is forwarded to the language runner or billed. A file or directory in the working directory may have the same name as the command word (a file named `submit`, for example). Then the words stay a language command and are forwarded, and a `HOSTED_UNAVAILABLE` refusal names the `prose cli ...` command. Language commands such as `prose status` are always forwarded; if the hosted harness is unavailable, the error also names `prose cli service status`. `prose help cli [COMMAND]` prints service help, with or without `--json` (help is text in every mode). A command option before `cli` (`prose --json cli run list`, `-j`, `--yes`, `--preview`, `--limit 5`) is never forwarded either: it exits 2 naming the option, and `details.suggestedArgv` moves it after the command path. `prose -- <WORDS>` always forwards to the language. `prose --help` starts with a "For agents" section (within its first 25 lines, before the runner options) and lists every command, the exit codes and the environment variables.

The CLI never guesses a misspelled or foreign command into execution. `cli run ls`, `cli run get`, `cli job lsit`, `cli organization list`, `cli whoami`, `--jsno`, `--format json`, `-y` and `-j` all exit 2 with "did you mean ...?" and the corrected command in `details.suggestedArgv`; rerun that command to proceed. The suggestion is always a complete command that parses: `cli models` suggests `cli model list`, `cli wallet show` suggests `cli wallet balance`, `cli run result RUN_ID` suggests `cli run show RUN_ID --file outputs/result.json`, `--amount 5` suggests `--amount-cents 500` (dollars converted; `--amount 5.50` is not converted and the reason says the option counts cents), `cli wallet topup 500` suggests `--amount-cents 500`, and `--limit 500` suggests `--limit 200`. A credit code or invitation token typed as an argument is never echoed; the suggestion reads it from standard input (`printf '%s\n' "$CODE" | prose cli wallet redeem --code-file - --yes`). `cli job update JOB_ID --name x` suggests `--spec-file -` with the JSON to pipe in as `details.suggestedStdin`. An unknown command lists every command noun. Option values are suggested and never substituted: `--output yaml` suggests `--output json`, and nothing is selected. `-h`, `prose cli help`, `prose cli <noun> help` and bare `prose cli` print help. The synonym tables are in the manifest (`prose cli service operations --json`, `grammar.intentInference`).

An invalid invocation (exit 2, `INVOCATION_INVALID`) gets an Action for its own cause. When one command fixes it, the Action names that command and `details.suggestedArgv` holds its arguments. The command is either your corrected argv (a misspelled noun, verb or option, a duplicate or extra token dropped, a global option moved before `cli`) or a follow-up such as `run list` for a missing `<RUN_ID>`. Every command the CLI hands you, including `details.resumeArgv`, `details.cancelArgv`, `details.suggestedArgv` and the commands quoted in reasons, keeps, in JSON or JSONL mode, your `--output`. In human mode an error that printed nothing else starts with the label itself (`OpenProse: INVOCATION_INVALID: ...`). In `--json` and `--output json|jsonl` mode every error of a `cli` command line has one shape: the `openprose.service-operation/1` envelope with `result: null` and the error as `problem`, so `jq .problem.details.suggestedArgv` works on a misspelled command too (`prose cli models --json`). When the argv names no operation, `operation` is `cli`. The error's `message` says what was wrong (`Unknown command.`, `Unknown option.` or `That command isn't quite right.`). A suggestion is the fix itself, not `--help`: an option the command does not take is removed (with its stray value), a guessed option is replaced (`--var K=V` is `--input K=V`, `--background` is `--detach`, `-o json` is `--output json`), `--quiet` and `--jq` are dropped with the reason, a verb typed before its noun is swapped (`cli submit run FILE`), a plural noun names its listing (`prose runs`), a quoted whole command line is split, and value mistakes with one fix name it (a run id without `run_`, `--wait 5` for `5s`, swapped `program save` arguments, unpadded or inverted `wallet usage` dates). Only language commands and the local runner commands (`cli doctor`, `cli harness`, `cli config`, `cli cleanup`) print a bare `openprose.runner-error/1`. A connection failure (`SERVICE_UNAVAILABLE` with no service answer) carries `details.reason` too.

Error details include the HTTP status, an allowlisted service code, and for 400, 405, 409 and 422 the sanitized service message. `GITHUB_LINK_REQUIRED` means the account must link GitHub in the web app; it does not mean the key is bad. `SERVICE_AUTH_REQUIRED` names `details.credentialSource` (`environment`, `store` or `none`), `details.credentialVariable` and, when known, `details.credentialProblem` (`missing`, `malformed` or `rejected`). A key from the environment wins over `cli auth login`, so replace or unset the variable: the Action says so for an environment key and names login only for a stored or missing key. `cli auth status` and `cli org list` classify keys the same way, and they, `cli auth login|logout` and `cli package ...` accept `--output` after the command path.

A not-found error (`SERVICE_RESOURCE_NOT_FOUND`, exit 10, not retryable) names what is missing: `details.resource` is `{kind, id}` (for example `{"kind": "job", "id": "..."}`), `details.reason` names the id, and `details.suggestedArgv` is the command that lists the ones that exist (`cli job list`, `cli run list`, `cli program list`, `cli org member list ORG`, `cli package list ORG` and so on); the Action quotes it. Run it and retry with an id it prints. A 404 on one of a run's files names the file and suggests `cli run show RUN_ID`. A rejected request (`SERVICE_REQUEST_REJECTED`) has an Action that names only the details present. `cli program delete ... --yes` and `cli job delete ... --yes` of something already gone exit 0 with `result.alreadyAbsent: true`, so retrying a delete after a lost response is safe. A `JOB_ID` that is not a UUID, or an `OWNER/SLUG` whose `OWNER` cannot be confirmed as you, exits 2 before anything is sent. A registry 404 (`cli package fetch|withdraw|list`) is `SERVICE_RESOURCE_NOT_FOUND` too, never the retryable `SERVICE_UNAVAILABLE`; an invalid `cli package` invocation is reported in the `openprose.service-operation/1` envelope with its cause in `details.reason`, and an empty human listing prints `No public packages in ORG.`.

Programs and results take the reference `cli program list` prints: `cli program save|visibility|delete|revisions` and `cli result publish|unpublish` accept `OWNER/SLUG` when `OWNER` is you (another owner, or an `OWNER` that cannot be confirmed because you have no program `SLUG`, exits 2 with the bare slug to pass; a confirmed one appears as `owner` in the plan), and `cli result list|show` accept a bare `SLUG` for your own program. Every program record carries `ref` (`OWNER/SLUG@rev_id`), ready for `run submit --from` and `job contract attach`; `cli program show SLUG@1` resolves a revision number of your own program. `cli result show OWNER/SLUG` without an id reads the newest publication, `cli example show` matches labels and names the nearest id, `VISIBILITY` takes any letter case, and `cli org rename ORG --name NAME` works like `org create`.

## Jobs

`job show` prints schedule times in RFC 3339 format. `job configure <JOB_ID> --interval-seconds N --yes` changes a schedule's cadence. It reads the current configuration token and bindings itself. The full `--config-file` form replaces everything and uses the service's snake_case request names. `job update` changes webhook jobs only. `job deliveries` exists only for webhook jobs.

## Credentials

The CLI talks to the production OpenProse service. It reads the key from `OPENPROSE_API_KEY` when that is set, otherwise from the OS credential store that `prose cli auth login` writes. See [credentials](service/credentials.md).

## Not offered

The CLI does not offer browser sign-in pages, the web helper, voice, editor state, signed share viewers or organization deletion. `prose cli service operations --json` lists each exclusion with its reason.
