# Evaluator provider contract

IMP-079, October 1, 2026. This explicit process capability assesses bound source snapshots through a selected provider. It does not interpret Markdown, execute subject work, discover credentials or change the selected kernel. Existing versioned process identifiers remain unchanged. The result includes evidence; each evaluation returns an assessment of its subject, not authority to act.

The process accepts `openprose.weave-input/1` with a null attempt and returns the existing single `judgment` envelope. Configuration and evaluation-plan bytes must be selected evidence. Bind every question, outcome mapping, provider/model selection and aggregation policy into the snapshot. Require exactly one kernel, at least one contract and evidence, checked source hashes, current observation and expiry. Gaps/future/expired observations produce `unknown` without HTTP. Malformed input is an evaluation error, with empty stdout and fixed stderr. Config and plan changes invalidate cached assessments through evidence identity.

An explicit all-required plan contains uniquely identified evaluations. Each identifies a contract instance, selected contract paths, opaque bindings, named choice questions, exhaustive outcome mappings and a provider profile. All selected contract sources must be covered by the plan. This checks declared coverage, not that questions express every requirement. One evaluation can include several questions; several evaluations can concern different instances of the same reusable contract. Preserve the whole governing source snapshot as context and identify each evaluation's subject explicitly.

Supported adapters are TypeSafe System One, OpenRouter Decisions, OpenAI Responses and Anthropic Messages. Their endpoints and authentication formats are native adapter metadata. Profiles explicitly name the requested model, exact allowed returned identifiers and credential variable. No model/provider fallback or automatic retries. OpenRouter Decisions is a distinct alpha protocol, not the OpenAI chat protocol. Both constrained generative outputs and typed native decisions are supported. Versioned prompt templates preserve supplied questions; parsers reject malformed or ambiguous responses rather than repairing them.

Choice criteria and labels are caller-defined. Each label maps explicitly to satisfied, violated or unknown for this evaluation. Label-only policies never manufacture probabilities. Native-threshold policies require provider-native distributions and confidence, enforce a unique maximum, and abstain below the configured probability/confidence/margin. Reject a probability policy on a generative-only profile before HTTP. These thresholds are caller policy, not a calibration claim.

An assessment is satisfied only if every required question/evaluation is satisfied. A known violation establishes nonfulfillment even if other assessments are unresolved; retain that distinction in the receipt. The legacy runtime judgment is unknown whenever any question remains unresolved, preventing action under an incomplete assessment. Otherwise a violation maps to work-needed. Evaluation failure is an error, not an invented unknown answer. No majority voting, inferred conditional applicability or automatic repair. Required independence cannot be established by batching questions: this initial explicit plan supplies no independence attestation and does not claim to enforce arbitrary independence requirements.

Bound calls serially by a total deadline, individual timeout, maximum call count, byte and token limits. Validate the entire plan, profiles and required credentials before the first call. Retain completed assessments if a later evaluation fails. Never return satisfaction after evidence expires. Receipts, when explicitly configured, record source/plan/config/request/response identities, native choices, optional native probabilities, model identities, usage, policy, per-evaluation status and final runtime judgment. No raw source contents, headers or credentials are written. A requested receipt that cannot be persisted fails the evaluation; callers retain uncertain charge reservations. A receipt is not a billing ledger.

Both Bun and Rust hosts use this same external process capability. Their independent runtime behavior is tested against the shared fixture corpus; provider parsing itself is not duplicated in the host. Test native mock responses, response truncation/refusal/duplicates, changed bindings, composition coverage, uncertainty, partial provider failure, expiry and actual process boundaries without network access. Live API qualification is separately authorized and retained in research.
